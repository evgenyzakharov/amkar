# Заметки для Claude

Как устроен проект и как с ним работать — в [README.md](README.md). Здесь то, что не видно из кода.

## Данные

- База в Supabase — единственный источник данных. Исходный `Амкар.xlsx` после импорта не обновляется.
- **Прямого доступа на запись в базу у Claude нет.** Массовые правки — это `.sql`-файл в `local/` (папка в `.gitignore`), который автор выполняет в SQL Editor. В начале файла — комментарий: что меняет и сколько строк должно затронуть. Перед массовой правкой напомнить запустить `backup.yml`.
- Читать базу можно самому: REST API Supabase с анонимным ключом из `.env` — у него только чтение.
- Явные id при вставке не двигают identity — после них `setval` (пример в [tests/schema.test.ts](tests/schema.test.ts)).
- Схема меняется только новой миграцией в `supabase/migrations` + тест в `tests/schema.test.ts`.

## Сайт

- Маршруты на hash: `#/season/2011-12` (в метке сезона `/` заменён на `-`), `#/match/<id>`, `#/player/<id>`, `#/players`, `#/history`, `#/leaders` (в адресе: `?scope=league` — только чемпионат, `?tab=clubs` — клубы 100/200) — [src/router.ts](src/router.ts). Параметры после `?` страницу не меняют: прокрутки наверх нет.
- «Лидеры» — итоги за карьеру из view `player_career_stats`, правила те же, что в `player_season_stats`; тест сверяет, что карьера равна сумме сезонов. «Рейтингами» автор называет свои оценки игроков — это другое, слово не занимать.
- Дашборды считаются во view миграции `20261018220000_dashboards.sql`: `season_summary` (история, минуты воспитанников), `team_streaks` (серии), `player_milestones` (рубежи). Общие правила: товарищеские не в счёт, неизвестный результат рвёт серию, с сезона 2021/22 — новый клуб (`NEW_CLUB_FROM` в [src/format.ts](src/format.ts)), серии через перерыв не тянутся. Тепловая карта сезона грузит выходы страницами по 1000.
- Цвета графиков проверены валидатором скилла dataviz: шкала минут — одна тёплая серая гамма (в тёмной теме перевёрнута); в полосах В–Н–П ничья — нейтральный серый, а не оливковый из квадратиков результатов (олива рядом с красным не различается при дальтонизме).
- Вид страниц игрока и сезона — по утверждённому макету «матч-программы» (`local/design/*.dc.html`): шрифты Oswald и IBM Plex Sans, акцент `#c8102e`. Полей без данных на сайте не показываем — ни заглушек, ни пустых блоков.
- Агрегаты считаются во view (`player_season_stats`), не на клиенте: PostgREST отдаёт не больше 1000 строк за запрос. Игра — минуты больше нуля или роль `start`/`sub`, товарищеские не в счёт.
- Части страниц из view грузятся отдельно (`part()` в [src/load.ts](src/load.ts)): пока автор не выполнил новую миграцию, остальная страница работает.
- Браузерные инструменты на машине автора не запускать. Страницы проверять сборкой в один IIFE-файл и прогоном в jsdom против настоящего Supabase. Вёрстку — скриншотами headless Edge (`msedge --headless=new --screenshot`): CSS в такой сборке зашит в JS — пересобирать перед снимком; окно уже ~500 px Edge не делает, телефон — через `<iframe>` шириной 390 px.

## Админка

- `#/admin` — вход по почте и паролю (Supabase Auth), права — `is_admin()`. Посетителям ссылок на неё не показываем, код админки грузится отдельным чанком.
- Пишет только через `Writer` ([src/admin/writer.ts](src/admin/writer.ts)): в приложении — supabase-js, в тестах — PGlite с теми же миграциями и RLS (`pgliteWriter` в [tests/db.ts](tests/db.ts)). Логику записи проверять там, а не моками.
- Транзакции на весь матч у PostgREST нет: карточка пишет по частям (шапка → голы → состав → пропуски), записанное сразу попадает в `base`, поэтому повтор после сбоя не дублирует. Состав: сначала upsert изменённых, потом удаление лишних — иначе ломается ссылка «кого заменил».
- Минуты на поле считаются по минутам замен (заменён на 64-й — 64, вышел на 64-й — 26, с доп. временем до 120). Минуты из базы, не совпадающие с подсчётом (старые матчи), при открытии карточки не пересчитываются — считаются введёнными вручную.
- Ошибки базы по-русски — [src/admin/dbErrors.ts](src/admin/dbErrors.ts). Новое ограничение в миграции без текста там уронит `tests/dbErrors.test.ts`.
- Соперник и тренер в карточке — текстом с подсказками из `team`/`coach`; новое название заводится в справочник при сохранении. Пустое поле оставляет `opponent_raw` из Excel: неоднозначные названия («Динамо») сами в справочник не попадают.
- Сезон в админке — вкладки `#/admin/season/<метка>[/grid|/squad|/transfers]`. Сетка: в ячейке минуты как в Excel (пусто, 0 — запас, «+» — минуты неизвестны, т/д/с — пропуск); роль и замены из карточки сохраняются, 0 делает запасным. Сравнение ячеек — по обеим строкам (состав и пропуск), а не по тексту: после сбоя в базе могут оказаться обе.
- Заявка: «воспитанник» — флаг игрока целиком (`player.academy`). Игрока с матчами сезона из заявки не убрать (ссылки нет, проверяет клиент), с итогами из Excel — не даст FK.
- Трансферы: клуб, которого нет в `team`, сохраняется текстом в `other_team_raw` и в справочник не заводится (в отличие от соперника в карточке матча).
- Строк сезона бывает больше 1000 (лимит PostgREST): состав и пропуски сезона грузятся постранично (`allRows` в [src/admin/queries.ts](src/admin/queries.ts)).
- Справочники `#/admin/teams` и `#/admin/coaches`. «Привязать» в соперниках ставит `opponent_id` всем матчам с этим `opponent_raw`, у которых клуб ещё не выбран; `opponent_raw` остаётся следом. Автор привязал все 192 названия из Excel к 130 клубам (18.10.2026).
- Клуб — одна строка `team`, прежние названия — `team_name` с годами (год начала сезона). Имя соперника на сайте — вычисляемый столбец PostgREST `opponent_name` (у трансфера — `other_team_name`): название на тот сезон → `team.name` → текст из Excel. Показывать соперника только через `opponentName()` и не забывать `opponent_name` в select.
- Сборная сезона — вкладка `…/best` (13 слотов `season_best_xi`), игроки — `#/admin/players` и `#/admin/player/<id>` (ФИО, дата рождения, основная позиция, воспитанник, ссылки `player_link`, фото с подписью). Фото — в публичном бакете `player-photos`, имя `<id игрока>-<время>.<расширение>` (новое фото — новый адрес, кэш не мешает); загружается сразу, отдельно от формы: файл → `player.photo_path` → прежний файл удаляется. Вместо файла можно дать ссылку `player.photo_url` (https://): сайт берёт картинку прямо с источника без referer, файл важнее ссылки, не открылась — силуэт. Хранилище — за интерфейсом `PhotoStore` ([src/admin/photos.ts](src/admin/photos.ts)), в тестах подделка.
- Видео матча — таблица `match_video` (полный матч / обзор, только YouTube и ВК; `site` вычисляет база по адресу). В админке — в карточке матча, сохраняется общей кнопкой; на сайте — кнопками-ссылками без встроенных плееров, запрос отдельный ([src/db/videos.ts](src/db/videos.ts)): нет таблицы — блока нет. Новый сайт — новая миграция, расширяющая выражение `site` и проверку `match_video_youtube_or_vk`.
- Вкладка `…/info` («Сезон»): лига, уровень, место, число команд, заметки, ссылки `season_link`; автор заполняет сам. Уровень (`season.tier`) — по схеме автора, не по официальной пирамиде: Премьер-лига 1, Первый дивизион 2, Вторая лига / Второй дивизион / Второй дивизион ФНЛ 3, Третья лига 4, Вторая лига «А» группа «Серебро» 4, Вторая лига «Б» 5.
- Голы за сезон: у сезона флажок `goals_from_matches` (вкладка «Сезон»). Выключен — `player_season_stats` берёт голы, передачи и пропущенные из `player_season_totals` (Excel), включён — из `goal`; столбец `goals_source` говорит, откуда. Пропущенные по матчам — только у вратарей (позиция `GK` в заявке сезона, иначе основная позиция игрока) и только пока он был на поле; гол без минуты — на начавшего матч. Включает флажок автор, когда сверка на той же вкладке сходится (решение автора 18.10.2026, первым — 2026/27).

## Дозаполнение матчей по протоколам

Правила автора (18.10.2026), по ним сделан 2026/27:

- Источник состава, замен («кто кого заменил»), голов и передач — отчёты Transfermarkt (`transfermarkt.com/spielbericht/index/spielbericht/<id>`, клуб — `verein/4128`). WebFetch туда не пускает, страница качается `curl` с браузерным User-Agent. Минута события на странице — в спрайте часов: `background-position: -X px -Y px`, минута = Y/36·10 + X/36 + 1, добавленное время — текстом «+N».
- Минуты на поле — из таблицы автора (он брал их из официальных протоколов), а не с Transfermarkt: там они расходятся на 1–3 минуты. Минуты замен выводятся из них.
- В обычное время максимум 90: вышедший в 90+ — на 90-й, 1 минута, ушедший — 90. Замена в перерыве (на Transfermarkt 46′) — 45.
- Передача засчитывается и за заработанный пенальти (на Transfermarkt «Penalty: Fouled player»); пенальти за игру рукой — без передачи, если автор не скажет иначе.
- Автор гола соперника — `goal.scorer_name` фамилией по-русски.
- Тур кубка — словами автора: «Второй раунд пути регионов». Схему расстановки (`match.formation`) с Transfermarkt не берём — у автора своя.
- Итоги Excel (`player_season_totals`) 2026/27 были по №15 включительно; №16 («Иртыш», 17.10) дописан в них SQL-ом 18.10.2026. Перед флажком «голы по матчам» сверка на вкладке «Сезон» должна показать «Всё сходится»; расхождения с Excel разбирает автор (пересматривает повторы), не угадываем.

## Разовый импорт из Амкар.xlsx

Импортёр в репозитории не хранится. Пока импорт не принят, всё лежит в `local/import/`: `import_amkar.py` (`py -3 -I import_amkar.py <xlsx> local/import`), готовые `01…04*.sql`, `import-report.md` с нестыковками и `verify.mjs` — прогон миграций и импорта на PGlite (`node local/import/verify.mjs`). Файл xlsx лежит у автора; путь спросить.

Как закодированы сезонные листы (`1995` … `202627`; `1994` пустой; сезонов 2018–2021 нет):

- Таблица «игрок × матч», в ячейке минуты: пусто — не в заявке, `0` — в запасе, `120` — дополнительное время. Серая заливка `D9D9D9` — игрока в это время не было в клубе.
- Результат матча — заливка заголовка: `D9EAD3` (в 2007 году `D0E0E3`) — победа, `FFF2CC` — ничья, `F4CCCC` — поражение. Синий шрифт заголовка — кубок, пурпурный — еврокубок или стыковые матчи. Счёта, дат и «дома/в гостях» в листах нет.
- Ячейки: `FF0000` — удаление, `F4CCCC` — травма. Если в ячейке есть минуты — случилось в этом матче (`appearance.sent_off` / `injured`), если пусто — пропуск матча (`absence`). На пустых ячейках ещё: `EA9999` — дисквалификация, голубая `C9DAF8` — отъезд в сборную (`national_team`; у фамилии тот же цвет значит «воспитанник»). Не импортировать: жёлтую `FFFF00`, сиреневую `D9D2E9` (отдых — автор это не ведёт), серую `CCCCCC` (не в клубе, как `D9D9D9`).
- Фамилия: голубая `C9DAF8` — воспитанник (раскраска только примерно с 2010 года, флаг ставится игроку целиком), светло-жёлтая `FFF2CC` — аренда.
- Столбцы итогов: ЧИ/ЧГ/ЧП — чемпионат (игры/голы/передачи), КИ/КГ/КП — кубок, ЛЕИ/ЛЕГ/ЛЕП — Лига Европы, Старт — игры в старте, Рустат — Index Rustat. У вратарей ЧГ отрицательный — это пропущенные. ЧИ, И и суммы — формулы, их не переносим. CA/Cons/CANew/ConsNew, Оценка и прочие рейтинги не берём.
- Столбец A меняет смысл по годам: позиция (`в/з/п/ф`), номер, с 2010 года позиция и номер раздельно, в 2011–2014 коды `в1/з2`.
- Строки составов с 2025/26 (`4-15(78)-92-17`): вне скобок — 11 номеров старта, в скобках — кто встал на эту позицию дальше. Это может быть и вышедший на замену, и переместившийся игрок старта, поэтому пару «кто кого заменил» импорт берёт из скобок, только если её подтверждают минуты. Часть строк Excel превратил в даты: «7-9» стало 9 июля.
- Матч без единого игрока в столбце — техническая победа (`match.awarded`; подтверждено автором: 1998, 2000, 2005 ×2, 2010, 2025).
- Ошибки Excel, которые поправил автор (минуты 2014/15 и 2015/16, «Топредо М», несыгранный «Иртыш» 2026/27), зашиты в начало `import_amkar.py`. Данных по 1996 «Зенит Ижевск» нет — так и оставлено.
- Справа на листе блоки «Пришли / Ушли / Остались» по окнам — это трансферы.
- Лист `Best XI` — сборная сезона за 1995–2025. Метку «2011/12» Excel превратил в дату 01.12.2011.

Не импортировать: тренерские листы (данные матчей автор пришлёт отдельно), «Худшие подписания», «Отмазы Хузина», «Амкар-2», выгрузки transfermarkt, Tiers/Rank/*-ratings, Sheet6/7/8/20, «Copy of 2008».

Однофамильцы и соперники при импорте не разводятся: одно написание — один игрок, соперник хранится текстом в `match.opponent_raw`. Разводим потом по указаниям автора.
